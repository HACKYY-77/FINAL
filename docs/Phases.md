# Phases.md: Project Phases

*One piece at a time. Never the whole thing at once.*

Hours are from kickoff (24 h total). A phase is checked off only after its acceptance test is actually run.

## Phase 0: Setup and contracts (h 0–1.5)

**Who:** All three

- [ ] Repo, branches, folder skeleton, .gitignore, requirements.txt.
- [ ] Write /shared/schemas and the mock sample files.
- [ ] Everyone confirms the contracts in Architecture.md.

**Acceptance test:** Each person can import a stub function that returns the mock output.

## Phase 1: Walking skeleton on mocks (h 1.5–6)

**Who:** A: stub infer + data download + prep script. B: build_model on mock_vector. C: API + viewer on mock_report/mock.glb.

- [ ] End-to-end flow runs with mock data.
- [ ] Dataset downloaded and converted to masks (A).
- [ ] Mock GLB opens in the viewer (C).

**Acceptance test:** Upload any image → viewer shows mock model + table. Mask samples look correct against source plans.

## Phase 2: Real core (h 6–12)

**Who:** A: train baseline U-Net. B: real vectorize (+ simple snap). C: real orchestration, overlay image, progress UI.

- [ ] First trained model with val mIoU logged (A).
- [ ] Real walls/openings/rooms from a real mask (B).
- [ ] Integration #1 at h 12: real plan → real 3D.

**Acceptance test:** A CubiCasa test plan produces a recognisable 3D model through the UI.

## Phase 3: Differentiators (h 12–18)

**Who:** A: OCR + scale solver, then baseline parser. B: topology validator, thickness/heights, better snapping. C: scale badge, warnings panel, override field, confidence overlay.

- [ ] Scale from OCR with door-prior fallback.
- [ ] Validator warnings visible in UI.
- [ ] Retrain with style augmentation (A) if time allows.

**Acceptance test:** A plan with labels gives metres within a few percent; a plan without labels shows "estimated".

## Phase 4: Evaluation and ablation (h 18–21)

**Who:** A leads the harness; B and C supply plans/ground truth and check numbers.

- [ ] Held-out set of 30–40 plans with real dimensions, varied styles.
- [ ] Baseline vs each added step, per-style results.
- [ ] Ablation table generated by one script.

**Acceptance test:** One command prints and saves the ablation table.

## Phase 5: Polish, demo, write-up (h 21–24)

**Who:** C leads; A and B fix bugs only.

- [ ] Demo rehearsal on unseen plans.
- [ ] Write-up with ablation table and honest limitations.
- [ ] Freeze main; tag release.

**Acceptance test:** A full 2–3 minute demo runs twice in a row without edits.

> **Tip:** Check off a phase only after you have tested it, not just looked at it. If Phase 3 slips, cut nice-to-haves, never Phase 4.
